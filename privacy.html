Privacy Policy

Last updated: October 26, 2026

This Privacy Policy explains what data nezzbot ("the bot", "we", "us") collects, why, how long it is kept, and how you can have it removed. By adding nezzbot to a server or using its dashboard, you agree to this policy.

1. Data we collect

nezzbot only processes data needed to provide its moderation, anti-nuke, logging, welcome, role and community features.

Configuration data

  • Discord IDs of servers, channels, roles and users that are referenced in settings.
  • Settings of each module (prefix, thresholds, whitelists, log channels, autoroles, welcome messages).

Moderation data

  • Moderation cases: warns, mutes, bans, kicks and jails, including the target user ID, the moderator ID, the reason and the timestamp.
  • Anti-nuke events: the user ID of the actor, the type of action, the timestamp and the punishment applied.

Message logs

  • When the logging module is enabled, the content, author ID, channel ID and attachment links of deleted and edited messages.
  • Message content is stored for a maximum of 7 days and then permanently deleted.
  • nezzbot does not store messages for any other purpose. Message content is otherwise processed in memory only, for example to detect spam or blocked links.

Server structure backups

  • When the anti-nuke module is enabled, a copy of the server structure: channels, categories, roles, permission overwrites and their names and ordering.
  • Backups contain no message history and no member lists.

Community features

These are stored only for the features that a server turns on or that members use.

  • Levels: for each member of a server with levels enabled, the user ID, experience points, level and number of messages counted. Message content is not stored.
  • Starboard: the IDs of starred messages and of their copies. The copy is posted by the bot in the starboard channel of the server and stays in Discord.
  • Tickets: the ticket number, channel ID, the user ID of the member who opened it, its status and timestamps. When a ticket is closed, a transcript file is posted to the log channel chosen by the server and is not stored by us.
  • Voice rooms: the channel ID of a temporary voice room and the user ID of its owner, until the room is deleted.
  • Giveaways: the prize, the host, the user IDs of members who entered and the winners.
  • Counting: the current number, the best number and the ID of the last member who counted.
  • Autoresponders and custom commands: the triggers, reply texts, embed fields, restrictions to channels and roles, role and emoji actions and the other settings configured by server administrators, and the ID of the member who created them. Cooldown markers are kept in memory-backed storage for at most one hour.
  • Reaction roles, verification and welcome settings configured by server administrators.
  • AFK status: the reason you set and the time, kept for at most 30 days or until you send a message.
  • Deleted and edited messages for the snipe commands: the content and author of the last few deleted or edited messages of a channel, kept in memory-backed storage for at most 2 hours and visible only to members with the Manage Messages permission.
  • Last.fm: if you link your account, your Discord user ID and your Last.fm username, until you remove the link with the unset command. The bot sends the username to the Last.fm API to show what you listen to.
  • Premium: the server ID, the tier, the expiry and, for a subscription bought through Discord, the ID of the Discord entitlement. We never receive or store payment details, payments are handled entirely by Discord.

Direct messages and rate limits

  • When a moderator warns, mutes, jails, kicks or bans you, the bot sends you a direct message with the action, the reason, the duration and the moderator (mention, username and ID). The message is sent once and is not stored by us, apart from the moderation case described above.
  • To limit abuse, the bot keeps short lived counters in Redis, for example the number of bans a moderator issued in the last minute. They contain the server ID and the user ID and expire by themselves within a minute.

Blocked users and servers

  • The operator can block abusive users and servers from using the bot. For this we store the user or server ID, the reason and the date.
  • To investigate abuse or to give support, the operator can generate a one use invite, valid for one hour, to a server the bot is in. The invite only lets the operator join as a regular member. It gives the operator no more access than any regular member of that server has.

Operational logs

  • Technical logs of the bot contain errors, Discord IDs and timestamps. They do not contain message content. Serious errors may be sent to a private channel of the operator.

Dashboard data

  • When you log in to the dashboard with Discord, we receive your user ID, username, avatar and the list of servers you belong to, along with your permissions in them. This is used only to show the servers you can manage.
  • Session data is stored in a cookie and on our servers until you log out or the session expires.
  • Audit log: when you change a setting in the dashboard we store the server ID, your user ID, the module, the kind of change, the names of the changed settings (never their values) and the time.
  • Draft settings: while you edit a page in the dashboard, the unsaved values are shared with the other managers of the same server who have the page open and kept for up to 5 minutes, then deleted. Personal pages such as the Last.fm link are never shared.
  • To protect the dashboard from abuse we keep short lived counters per IP address and user ID. They expire within 10 minutes and are not used for anything else.

We do not collect email addresses, passwords, payment details or direct messages. We do not sell or share data with advertisers.

2. How we use data

  • To run the features you enabled on your server.
  • To enforce moderation and anti-nuke settings.
  • To let server administrators view and change settings in the dashboard.
  • To prevent abuse of the bot and to fix errors.
  • To apply the premium benefits of a server that has a subscription.

3. Storage and security

Data is stored in a PostgreSQL database and a Redis cache operated by us. Access is limited to the bot operator. We use reasonable technical measures to protect data, but no system is completely secure.

4. Retention and deletion

  • Message logs: deleted automatically after 7 days.
  • When nezzbot is removed from a server, all data for that server (settings, moderation cases, backups, logs and community feature data) is deleted immediately.
  • Snipe data: deleted automatically after 2 hours. AFK status: after 30 days.
  • Levels, giveaway entries and other community data: kept until the server resets them or removes the bot.
  • Your Last.fm link: kept until you remove it.
  • Rate limit counters expire within a minute (dashboard login counters within 10 minutes).
  • Dashboard audit log: deleted automatically after 90 days.
  • Dashboard sessions are deleted when you log out or when they expire.
  • You can request deletion of data about you at any time through the support server. Verified requests are completed within 30 days.

5. Data sharing

Data is shared only with Discord, through its API, as required for the bot to work, with Last.fm if you link your account, with Discord's subscription system for premium, and with authorities when we are legally required to do so. Server administrators can see moderation cases and logs of their own server.

6. Children

Discord requires users to meet a minimum age. nezzbot is not directed to children, and we do not knowingly collect data from users below the minimum age required by Discord.

7. Your rights

You may ask us to tell you what data we hold about you, to correct it, or to delete it. Contact us through the support server.

8. Changes

We may update this policy. The date at the top shows the latest revision. Continued use of the bot after a change means you accept the updated policy.
